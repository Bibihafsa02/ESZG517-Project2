SECTION A — PROTOCOL COMPARISON: MQTT vs CoAP (10 Questions)
==============================================================================

Q1. What transport protocol does MQTT use? What transport protocol does CoAP
    use? What is the fundamental difference between the two?

    Answer: MQTT uses TCP, CoAP uses UDP; the key difference is TCP is connection oriented and reliable, while UDP is lightweight but less reliable.

==============================================================================

Q2. In today's session, MQTT used a publish/subscribe model and CoAP used a
    request/response model. Explain the difference between these two models
    in your own words using the smart home scenario as an example.

    Answer: In MQTT’s publish/subscribe, a sensor publishes light state and any subscriber (like a mobile app) gets updates; in CoAP’s request/response, the app must directly query the room resource to know the light state.

==============================================================================

Q3. Report the CoAP GET latency values you measured during the session:

    Min latency     : 0.65 ms
    Max latency     : 4.14 ms
    Average latency : 1.11 ms

    Based on these numbers, is CoAP fast enough for real-time light control
    in a smart home? Justify your answer in 2-3 sentences.

    Answer: This is fast enough for real time light control, delays under ~100 ms are generally acceptable for smart home responsiveness.

==============================================================================

Q4. In your L3 MQTT publisher, the light relay topic used retain=True.
    CoAP does not have a retain flag. How does CoAP handle the same problem
    of "what is the current state of the light?"

    Answer: CoAP solves the retain problem by allowing a client to send a GET request at any time to retrieve the current state from the server.

==============================================================================

Q5. MQTT uses TLS for security. CoAP uses DTLS. Why can't CoAP use TLS?
    What is the key difference between TLS and DTLS?

    Answer: CoAP can’t use TLS because TLS is designed for stream based TCP; DTLS is the datagram based equivalent that works with UDP.

==============================================================================

Q6. In today's session, the CoAP server and client both ran on your laptop.
    In a real smart home, where would the CoAP server run? Where would the
    CoAP client run? Give a specific example.

    Answer: In a real smart home, the CoAP server would run on the IoT device e.g., a smart bulb or relay controller, and the CoAP client would run on the mobile app or home automation hub.

Q7. A student says: "CoAP is always better than MQTT because UDP is faster
    than TCP." What is wrong with this argument? Give one scenario where
    MQTT is clearly the better choice and explain why.

    Answer: The argument is flawed because speed isn’t the only factor, MQTT’s reliability and QoS matter. For example, publishing temperature data to the cloud is better with MQTT since TCP ensures delivery even over unstable networks.

Q8. In the CoAP server code, render_get returns aiocoap.CONTENT and
    render_put returns aiocoap.CHANGED. What do these response codes mean?
    What is the equivalent concept in HTTP?

    Answer: aiocoap.CONTENT means a successful GET with data, aiocoap.CHANGED means a successful PUT update; in HTTP, these correspond to status codes like 200 OK and 204 No Content.

Q12. In the TLS demo, the same message was sent but Wireshark showed no
     readable payload. Explain in one sentence why TLS prevents Wireshark
     from seeing the message content even though both demos used the same
     loopback interface.

     Answer: TLS encrypts the payload before transmission, so even though Wireshark can capture the packets on the loopback interface, the message content is scrambled and unreadable without the encryption keys.
